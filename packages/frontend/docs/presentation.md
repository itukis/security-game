# SecurePatch Quest

## AI生成コード時代のセキュリティ学習ゲーム

AIが生成したログイン画面を診断し、  
「動く」だけでなく「安全に直す」流れを体験するフロントmockです。

---

# 背景

## AI / Vibe codingで開発は速くなった

- 誰でも短時間で画面やコードを作れる
- まず動くものを作るハードルが下がった
- その一方で、安全性の確認は後回しになりやすい

> 動くコードが、安全なコードとは限らない

---

# 課題

## 初学者は「直す感覚」を学びにくい

- 脆弱性の名前だけでは、原因コードが見えづらい
- 選択式だけでは、修正後の確認まで体験しづらい
- 本物の攻撃やDBを使う教材は、準備と安全管理が重い

---

# 解決策

## 攻撃確認 → 原因確認 → 修正 → 再テスト

SecurePatch Questは、セキュリティ学習をゲームの流れにします。

1. 弱点を疑似攻撃で確認
2. 原因コードを読む
3. 修正案を選ぶ
4. 再テストで防御確認

---

# 価値

## 「選ぶ」だけで終わらない学習体験

- Secure Code Warriorのような選択式学習の良さを参考にしつつ
- 原因コードと修正後の再テストまでつなげる
- AI生成コード時代に必要な「安全に直す力」を育てる

# 現在のフロントmock

## API未接続でも一通り体験可能

- mockデータのみで動作
- 本物の攻撃処理は実行しない
- DB接続もしない
- 修正案選択で疑似判定
- 正解なら防御成功、不正解なら防御失敗

---

# 技術構成

## Cフロントの担当範囲

- Next.js `16.2.6`
- TypeScript
- Tailwind CSS `^4`
- App Router
- `components/` にUIを分割
- `lib/api/challenges.ts` にAPI結合口を集約

---

# API結合予定

## バックエンド接続へ差し替えやすい構成

- `GET /problems/:id`
- `POST /problems/:id/verify`
- request: `{ patch: "<unified diff string>" }`
- verifyは5〜15秒想定
- フロントはloadingとエラー表示を用意済み
